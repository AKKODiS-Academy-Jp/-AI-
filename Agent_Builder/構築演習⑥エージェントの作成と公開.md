#### 共有メニューの機能
画面の機能概要エージェントの利用範囲（アクセス権）を設定する共有メニューです。

選択肢は以下の3つです：
- **組織内の全員**
  - 同一テナント内のすべてのユーザーが利用可能
- **組織内の特定のユーザー**
  - 指定したユーザーのみ利用可能
  -  ユーザー選択欄に対象ユーザー・グループを入力  
   - 名前 / メールアドレスで検索
   - 候補リストから選択
   - 対象ユーザーを確定（複数人選択可）
   - 「適用」ボタンをクリック
- **自分のみ**
  - 作成者本人のみ利用可能（デフォルトに近い安全設定）

> [!CAUTION]
> この設定は「誰が使えるか」だけを制御するものです。
> 意図しないアクセス権付与のリスクに注意してください。
> 共有設定におけるリスク一覧（⚠ 意図しないアクセス権付与に注意）
> | リスク分類 | 内容 | 発生条件 | 具体的な影響 |
> |-----------|------|----------|-------------|
> | 想定外のユーザーへの公開 | 「組織内の全員」を選択すると、対象範囲が一気に拡大する | 全員公開を選択 | 検証前エージェントや未完成コンテンツが全社公開される<br>内部ノウハウ・情報が広範囲に利用可能になる |
> | 機密・入力データの間接露出 | エージェントが社内データや業務ロジックを扱う場合、公開により情報経路が拡張される | SharePoint / Dataverse / API / プロンプト連携あり | 利用者増加により意図しない情報アクセス経路が発生<br>機密情報の参照機会が拡大 |
> | 権限設計の誤認（ユーザー権限 vs データ権限） | この設定は「エージェントの利用可否」であり、データアクセス権ではない | 共有範囲だけを見て安全と誤認 | データ権限は別管理のため制御が不十分な状態になりやすい<br>結果として閲覧機会が拡大する |
> | ガバナンス違反・DLP逸脱 | 広範囲公開により未統制の接続・処理が利用される可能性 | 全員公開＋コネクタ/フロー連携あり | 未審査の外部コネクタ利用<br>DLPポリシー逸脱<br>内部統制・監査リスク増大 |

### 設計原則（要約）

| 原則 | 意味 | 実務ポイント |
|------|------|-------------|
| 最小権限 | 必要最小限のアクセスのみ許可 | 初期は「自分のみ」→段階的に拡張 |
| 環境分離 | Dev / Test / Prod を分ける | 誤公開・誤接続を防ぐ |
| 共有制御 | 公開範囲を段階管理 | 全員公開は最終段階のみ |
| DLP適用 | データ流出を防ぐ | コネクタ設計が最重要 |
| RBAC | 役割ベースで管理 | Entra ID / Dataverse連携前提 |

###  ⚠ 重要な前提（誤解されやすいポイント）

| 観点 | 説明 |
|------|------|
| 共有設定 | 「誰が使えるか」を制御する |
| データ権限 | 「何にアクセスできるか」を制御する |
| 結論 | 両者は別管理（＝片方だけでは安全にならない） |
